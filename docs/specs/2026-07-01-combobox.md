# Spec — Combobox (Compose layer)

`registry/ui/combobox.tsx`. An always-searchable, single-select autocomplete. A thin,
opinionated preset over `registry/ui/select.tsx`. Mirrors `registry/ui/tabs.tsx` (`items[]`)
and reuses Select's slot vocabulary 1:1.

`registry/ui/select.tsx` is already built on the `components/ui/combobox` primitive: its
searchable single-select branch renders `ComboboxPrimitive.Input` inside an `InputGroup`.
So a searchable single-select Select IS a combobox. Combobox is therefore a strict subset of
`<Select searchable multiple={false} />`; its only value-add is a narrower, discoverable API
(the shadcn-canonical name, autocomplete mental model, no mode-selection props). See ADR-1.

## Ground truth
- Primitive: `components/ui/combobox.tsx` (base-ui `@base-ui/react` Combobox) exports
  `Combobox` (Root), `ComboboxContent`, `ComboboxList`, `ComboboxItem`, `ComboboxEmpty`,
  `ComboboxValue`, `useComboboxAnchor`, plus chips parts (multi only — unused here).
- Root `Combobox<string, false>` relevant props: `value`, `defaultValue`, `onValueChange`,
  `open`, `defaultOpen`, `onOpenChange`, `disabled`, `name`, `filter`, `itemToStringLabel`,
  `items`, `onInputValueChange`.
- Sibling `registry/ui/select.tsx` searchable-single branch: `InputGroup` wrapper +
  `ComboboxPrimitive.Input` (`render={<InputGroupInput/>}`) + `InputGroupAddon` adornment;
  `ComboboxContent` → `ComboboxList` (render-callback) → `ComboboxItem`; `ComboboxEmpty`.
  Reuses `useSelectItems` for the `value→item` index, default filter, and `itemToStringLabel`.

## API
```ts
export interface ComboboxItem {
  value: string;               // required; stable React key + controlled value. "" is valid.
  label: ReactNode;            // display label; string/number drive default filter, else falls back to value
  disabled?: boolean;          // unselectable
  itemClassName?: ClassValue;  // per-item, merged AFTER root itemClassName
}

export interface ComboboxProps {
  items: ComboboxItem[];

  value?: string;                                     // prop presence = controlled (incl. undefined)
  defaultValue?: string;
  onValueChange?: (value: string | undefined) => void; // undefined = no selection

  open?: boolean;
  defaultOpen?: boolean;                              // @default false
  onOpenChange?: (open: boolean) => void;

  placeholder?: string;                               // @default "Pick an option"
  emptyMessage?: ReactNode;                           // @default "No results"
  clearable?: boolean;                                // @default false; mirrors Select
  filter?: (item: ComboboxItem, query: string) => boolean; // escape hatch; @default case-insensitive contains on label, fallback value

  disabled?: boolean;
  name?: string;                                      // native form field name
  id?: string;                                        // on the input, for <label htmlFor>/Field
  "aria-describedby"?: string;
  "aria-invalid"?: AriaAttributes["aria-invalid"];

  className?: ClassValue;        // InputGroup wrapper (bordered control)
  inputClassName?: ClassValue;   // the <input>
  contentClassName?: ClassValue; // popover content container
  itemClassName?: ClassValue;    // default item className, merged with item.itemClassName
  emptyClassName?: ClassValue;   // <ComboboxEmpty/> className
}
```
- `ComboboxProps` is an explicit interface (NOT `extends Omit<Root.Props…>`): delegating to
  Select means the passthrough surface is deliberately closed — only the enumerated props are
  forwarded. No `...rest` spread. Anything unlisted → use `Select` or the primitive.
- No `searchable`/`multiple` props: Combobox is *always* searchable, *never* multiple.
- No `triggerClassName` (no trigger button exists), no `valueClassName`, no `clearClassName`,
  no `listClassName` — Select exposes none of these; stay aligned.
- Slot names → primitive `data-slot`: `className`→`InputGroup` wrapping
  `data-slot="combobox-input"`; `inputClassName`→`data-slot="combobox-input"` (`<input>`);
  `contentClassName`→`ComboboxContent`; `itemClassName`→`data-slot="combobox-item"`;
  `emptyClassName`→`ComboboxEmpty`.
- Per-item class merged AFTER root-level: `cn(itemClassName, item.itemClassName)`.
- Implementation: render `Select` with `searchable` forced on and `multiple` unavailable,
  passing the enumerated props 1:1 (slot names already match). Reuses `useSelectItems`, the
  adornment/clear machinery, and value/open controlled-state hooks — no duplicated logic. If
  Select's discriminated-union typing makes direct delegation awkward, fall back to a minimal
  standalone render mirroring only Select's `effectiveSearchable` branch, but the default
  filter, `itemToStringLabel`, and value/open hooks MUST be imported/shared, never re-implemented.

## Behavior / edge cases (tests)
1. Renders an input + popover from `items`; no trigger `<button>` exists in the DOM.
2. Uncontrolled: typing filters; clicking an item selects it and fills the input; selecting
   another updates.
3. Controlled: click fires `onValueChange(value)`; selection does not change until `value`
   prop updates; `value={undefined}` stays controlled and shows placeholder.
4. `item.value === ""` is a valid selection (label shown, not empty state).
5. Per-item `disabled` blocks selection; root `disabled` blocks all interaction.
6. `placeholder` shown when value is `undefined`; defaults to `"Pick an option"`.
7. No matches → `emptyMessage` (default `"No results"`); empty `items` → same.
8. `clearable={false}` (default): no clear button. `clearable={true}`: clear appears with a
   value on adornment-hover / focus-within; clearing emits `undefined`.
9. `filter(item, query)` overrides the default case-insensitive substring match.
10. `cn(itemClassName, item.itemClassName)` merge order; `inputClassName` on the input,
    `className` on the wrapper — never the same element.
11. `name` set → hidden input carries the selected value in form submission; `id`/`aria-*`
    land on the input.

Coverage gate: lines ≥90, functions ≥90, branches ≥85, statements ≥90
(`pnpm exec vitest run registry/ui/combobox.test.tsx`).

## Out of scope (→ `Select` or primitives)
- Non-searchable plain dropdown → `<Select />`.
- Multi-select / chips → `<Select multiple />`.
- Async / server-side / eager loading → `<Select loadItems … />`.
- Grouped, heterogeneous, or custom item bodies; virtualized lists; creatable / free-text
  values not in the list → `components/ui/combobox` primitives directly.
- Custom clear-icon styling, `valueClassName`, list-container styling → primitives.
- Editing `components/ui/**` — forbidden.

### ADR-1: Ship Combobox as a thin preset delegating to `Select`, not a from-scratch reimplementation.
**Decision**: `Combobox` forces `searchable` on and makes `multiple` unavailable, forwarding a
closed, enumerated prop set to `Select`. Near-zero new logic; one opinion baked in.
**Why**: A searchable single-select Select already IS a combobox (shares the
`components/ui/combobox` primitive). A parallel implementation would duplicate `useSelectItems`,
the default filter, and value/open state hooks for no behavioral gain. Delegation keeps it
strictly 80/20 and surgical, and dissolves the trigger-vs-input / searchable-scope / default-drift
ambiguities (no trigger, no non-searchable mode → nothing to disambiguate). Fallback if the naming
/discoverability value is judged insufficient: do not ship a component — document
`<Select searchable />` under the "Combobox" doc page instead.
