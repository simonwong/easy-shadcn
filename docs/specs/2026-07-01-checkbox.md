# Spec — CheckboxGroup (Compose layer)

`registry/ui/checkbox-group.tsx`. Flattens the shadcn/ui Checkbox primitive into one
`items`-driven multi-select group. **Exact mirror of `registry/ui/radio-group.tsx`**,
differing only in that selection state is an array (`string[]`, multi-select) instead of a
single `string`. Follows Group root delegation (ADR-0003).

## Ground truth (base-ui @1.4.0)
- `CheckboxGroup.Props` (`@base-ui/react/checkbox-group`): `value?: string[]`,
  `defaultValue?: string[]`, `onValueChange?(value: string[], details)`, `disabled?: boolean`,
  `allValues?: string[]` (for an optional `parent` "select all" — out of scope), + div props.
  **value is an ARRAY** (multi-select native). The root delegates controlled/uncontrolled
  resolution and dev-mode warnings; the Compose layer never hand-rolls `string[]` state.
- A child `@base-ui/react/checkbox` joins the group by its `value` prop
  (`value = valueProp ?? name`, `CheckboxRoot.js:94`).
- Item `disabled` is OR-ed with group `disabled` inside base-ui
  (`CheckboxRoot.js:92`: `disabled = rootDisabled || fieldItemContext.disabled || groupContext?.disabled || disabledProp`),
  so item `disabled:false` cannot re-enable a disabled group. No manual disabled math.
- There is **no styled `CheckboxGroup` in `components/ui/`** (only `checkbox.tsx`), and
  `components/ui/**` is read-only. So the Compose file imports the group root directly from
  base-ui and the styled item from the primitive:
  ```ts
  import { CheckboxGroup as CheckboxGroupRoot } from "@base-ui/react/checkbox-group";
  import { Checkbox } from "@/components/ui/checkbox";
  ```
  The raw base-ui root is unstyled, so the Compose layer bakes RadioGroup's layout in itself:
  `className={cn("grid w-full gap-2", className)}` (RadioGroup gets this from its styled
  `components/ui` wrapper). Keeps `components/ui/**` untouched. If a shadcn `checkbox-group`
  primitive is later added via `pnpm dlx shadcn@latest add`, swap the root import to it and
  drop the baked layout.

## API
```ts
export interface CheckboxGroupItem {
  description?: ReactNode;
  descriptionClassName?: ClassValue;
  disabled?: boolean;
  itemClassName?: ClassValue;
  label: ReactNode;
  labelClassName?: ClassValue;
  optionClassName?: ClassValue;
  value: string;
}

export interface CheckboxGroupProps
  extends Omit<
    CheckboxGroupPrimitive.Props,
    "children" | "defaultValue" | "onValueChange" | "render" | "value"
  > {
  defaultValue?: string[];
  descriptionClassName?: ClassValue;
  itemClassName?: ClassValue;
  items: CheckboxGroupItem[];
  labelClassName?: ClassValue;
  onValueChange?: (
    value: string[],
    eventDetails: CheckboxGroupPrimitive.ChangeEventDetails
  ) => void;
  optionClassName?: ClassValue;
  value?: string[];
}
```
- Field-for-field identical to `RadioGroupItem` / `RadioGroupProps`, except `value`/
  `defaultValue` are `string[]` and `onValueChange`'s value is `string[]` with
  `CheckboxGroupPrimitive.ChangeEventDetails`.
- `disabled` and `allValues` are NOT declared explicitly — they flow through `...rootProps`
  from `CheckboxGroupPrimitive.Props`, exactly as RadioGroup lets `disabled` flow through.
- Adopt the primitive's native `ChangeEventDetails`. No custom `{ item, checked }` object, no
  `checked` field, no `item` payload, no `indeterminate` in the type.
- Per-item class merged AFTER group-level so per-item wins: `cn(groupClass, item.class)`.
- `baseId` from `useId()`. IDs derive from index (not `item.value`): values may contain
  whitespace, which would break the space-separated `aria-labelledby` / `aria-describedby`
  token lists. Rendered `<label>` wrapper is hand-rolled (not a shadcn part), named
  `optionClassName` to mirror RadioGroup.

## Behavior / edge cases (tests → `checkbox-group.test.tsx`)
1. Renders a checkbox + label (+ optional description) for every `items` entry.
2. Uncontrolled multi-select: clicking one checkbox toggles it without affecting others; a
   second click clears it.
3. `defaultValue={["a", "c"]}` initializes items `a` and `c` as checked.
4. Controlled `value` + `onValueChange`: clicking fires `onValueChange(nextValue: string[], details)`
   with the updated array; the UI does not change until the `value` prop updates.
5. Group `disabled` blocks toggling every checkbox.
6. Group `disabled` + item `disabled:false` still keeps that item disabled (item `false` does
   NOT bypass group).
7. Per-item `disabled:true` (group enabled) blocks only that item.
8. Merges group + per-item classNames on the label wrapper, checkbox, label, and description
   slots via `cn(groupClass, itemClass)` (per-item wins).
9. Empty `items` renders the group root with no checkboxes.
10. IDs derive from index: `labelId = ${baseId}-${index}-label`,
    `descriptionId = ${baseId}-${index}-description`; `aria-describedby` is absent when
    `item.description === undefined`.
11. `className` and native div props (`data-*`, `id`, `style`) forward to the root.

Coverage gate: lines ≥90, functions ≥90, branches ≥85, statements ≥90 (trivially met — the
component is wiring, not a state machine, per ADR-0003).

## Out of scope (→ primitives)
Heterogeneous per-item markup; a `parent` / "select all" meta-checkbox (use base-ui
`CheckboxGroup` `parent` + `allValues` directly); per-item `indeterminate`; nested/hierarchical
groups; custom indicators beyond className overrides; bespoke keyboard behavior beyond base-ui's
native handling; form-name/id generation; runtime enforcement of controlled vs. uncontrolled
(delegated to the primitive, which warns in dev — no throw, matching RadioGroup/Tabs/Accordion).
