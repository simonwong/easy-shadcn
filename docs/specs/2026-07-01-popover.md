# Spec — Popover (Compose layer)

`registry/ui/popover.tsx`. Flattens shadcn base-ui Popover parts (`Popover`, `PopoverTrigger`,
`PopoverContent`, `PopoverHeader`, `PopoverTitle`, `PopoverDescription`) into one flat-prop
component: a **trigger** (the user's own element, rendered via `render`) plus a **popup** composed of
optional **header** (title/description), **body** (`content`), and optional **footer**. Mirrors
`registry/ui/tooltip.tsx` (trigger-via-render + positioning) and `registry/ui/card.tsx`
(header/body/footer slot guards).

## Ground truth (base-ui, from `components/ui/popover.tsx`)
- `PopoverContent` forwards **exactly five** positioning props — `side`, `sideOffset`, `align`,
  `alignOffset`, `anchor` (lines 24–27) — plus `className`, native div/`data-*`/event props.
  Defaults: `side="bottom"`, `sideOffset=4`, `align="center"`, `alignOffset=0`, `anchor` = trigger.
  Nothing else from the floating-UI config surface is exposed by the primitive.
- The primitive renders **no `PopoverArrow`**. Arrows do not exist in this design.
- The `Popup` element already ships the compose-appropriate look
  (`w-72 flex flex-col gap-2.5 rounded-lg bg-popover p-2.5 text-popover-foreground text-sm shadow-md ring-1`);
  header/body/footer become flex children with consistent gap. **No style inversion needed.**
- `PopoverRoot` accepts control props `open`, `defaultOpen` (`false`),
  `onOpenChange(open, details)`, `disabled` (`false`).
- Existing `data-slot`s: `popover` (root), `popover-trigger`, `popover-content` (the popup),
  `popover-header`, `popover-title`, `popover-description`.

## API
```ts
type RootProps = ComponentProps<typeof PopoverRoot>;
type ContentProps = ComponentProps<typeof PopoverContent>;

export interface PopoverProps
  extends Omit<ContentProps, "title" | "content" | "children">,
    Pick<RootProps, "defaultOpen" | "disabled" | "onOpenChange" | "open"> {
  children: ReactElement;    // the trigger element (rendered via render={children})
  content: ReactNode;        // popup BODY slot — distinct from the PopoverContent primitive
  title?: ReactNode;
  description?: ReactNode;
  footer?: ReactNode;
  headerClassName?: string;
  titleClassName?: string;
  descriptionClassName?: string;
  contentClassName?: string; // the body wrapper (data-slot="popover-body")
  footerClassName?: string;
}
```
- **Extend `ContentProps`, not a hand-written type** (Tooltip pattern): inherits in one shot the five
  positioning props (`side`, `sideOffset`, `align`, `alignOffset`, `anchor`), `className`, and native
  popup div props with the primitive's exact types. **`className` is inherited — never re-declared**
  (Card/Tooltip rule); it lands on the popup (`data-slot="popover-content"`).
- Control props come from `RootProps` via `Pick`, so `onOpenChange`'s `(open, details)` signature is
  the primitive's, not re-typed.
- **Zero floating-UI type imports** (`Side`, `Align`, `Boundary`, `Padding`, `CollisionAvoidance`,
  `OffsetFunction` all gone) — everything derives from `ComponentProps<typeof …>`.
- `children` is the trigger, rendered via `PopoverTrigger render={children}` — no wrapper, no
  `triggerClassName`; the child itself becomes the trigger.
- `content` is the popup **body**, distinct from the `PopoverContent` primitive (the popup
  container). Body wraps `content` in `<div data-slot="popover-body">` so `contentClassName` has a home.
- `footer` is a compose-only helper slot — plain `<div data-slot="popover-footer">`, no `PopoverFooter`
  primitive exists.
- Reuse Card's `hasNode` guard verbatim (`null`/`undefined`/`boolean` → absent; `0`/`""` render).
  Header renders only when `title` or `description` is present. No `cn` needed anywhere — every class
  override is a single value assigned directly (no divider-merge like Card).
- Compose-added `data-slot`s: `popover-body` (body wrapper), `popover-footer` (footer). Distinct name
  `popover-body` avoids collision with the primitive's `popover-content` (the popup container).

## Behavior / edge cases (tests)
1. Renders `children` as the trigger with `data-slot="popover-trigger"` and **no extra wrapper button**
   (single button in the tree).
2. Closed by default; `defaultOpen` and controlled `open` show the popup; `open={false}` keeps it closed.
3. `onOpenChange` fires with `(next, details)` on trigger interaction.
4. `disabled` blocks opening.
5. Renders `title` / `description` / `content` / `footer` into their slots (query `popover-title`,
   `popover-description`, `popover-body`, `popover-footer`).
6. Header absent when neither `title` nor `description` present; footer/body absent when their node is absent.
7. Falsy-but-valid nodes (`0`, `""`) render; `null`/`undefined`/`boolean` treated as absent.
8. Forwards every `xxxClassName` to its slot and `className` + `data-*` to the popup (`popover-content`).
9. Forwards `side` (and the other positioning props) to the positioner (`data-side` on/around the popup,
   per Tooltip's assertion style).

## Out of scope (→ primitives)
- Custom arrows (`PopoverArrow`) — the primitive renders none; arrow decoration is a
  primitive-composition task.
- Advanced positioning: `positionMethod`, `collisionBoundary`, `collisionPadding`, `sticky`,
  `arrowPadding`, `disableAnchorTracking`, `collisionAvoidance` — compose `PopoverContent` +
  `PopoverPositioner` directly.
- Trigger styling via `triggerClassName` — pass a pre-styled element as `children` (Tooltip parity).
- Heterogeneous popup layouts, multiple bodies, "insert node between header and body," render props
  (`renderHeader`/`renderFooter`), a `slots` object.
- `modal` mode, `PopoverBackdrop`, portal/viewport control, `actionsRef` imperative close/unmount,
  `onOpenChangeComplete` animation callbacks, form integration.
